## M1 · 先做真实使用验证

1. 在 iPhone Safari、Android Chrome 各录入至少 10 条，覆盖长文本、表情和中英文；验证键盘不遮住保存、关闭时不会丢草稿、屏幕阅读器焦点。
2. 在用户指定的 GitHub 仓库发布 HTTPS 页面并添加主屏幕，测试重启设备后离线打开、更新时编辑状态和浏览器数据回收提示；实际发布状态见 deployment.md。
3. 确认「待理解记录」入口是否足够容易发现；必要时调文案和计数，不增加一整套笔记目录。
4. 验证恢复到另一个浏览器；确定是否需要合并导入。当前归档为 schema v3，支持旧 v1/v2，全量替换由用户确认。

## M2 · 第一个真实 AI adapter

1. 选一个实际可用、用户愿意承担成本的模型；确定 CORS/HTTPS/自建代理策略。界面先展示提交原文与目的，再经用户主动操作发请求。
2. 实现 `AIAdapter` 的远程版本，结构化摘要/一个可跳过问题/来源；设置 AbortSignal 与超时；拒绝无证据输出。
3. 注入 App 中的 AIService，连接 pending 记录的显式理解动作；busy 不能覆盖原始已保存状态；失败可手动重试。
4. Key 仅存内存，显示发送边界；导出/日志/缓存中检查不含 Key。模型文本不能执行工具，也不能改写原记录。
5. 用真实样本验证「读过但误解」「过度推断」「指令注入」「断网/限流」「用户退回」；用户确认不是自动完成的步骤。

M2 完成之前不得在 UI 宣称 AI 已观察用户或已掌握知识。

## M3 · 由证据驱动的可选扩展

- 本地模型：下载、性能、内存、许可、离线推理实测后决定。不要为接口占位而默认下载权重。
- 原生包装：用户需要 App Store 或安全密钥存储时评估 Capacitor/Expo 与 SQLite 迁移。
- 账号/云同步：有多设备需求才新增设计记录；先决定 E2E 加密、版本、删除墓碑和冲突副本。
- 「我学会了」：设计用户主动确认的知识迁移，不能由模型自动把「我不会」改成「我会」。

## 开发边界

阅读 architecture.md 后再改状态模型；任何 schema 修改必须同时更新导入校验、迁移策略和归档测试。不得用关键词规则填充 AI understood。不得把真实用户记录写入示例、测试夹具或提交。每轮更新 verification.md，分清本轮自动化、真机手动和未验证内容。
